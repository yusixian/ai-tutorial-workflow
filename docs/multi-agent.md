# 多会话协作

一套长教程通常会同时有好几条线：渲染统整、动效、选图、逐字稿、配音、预告片、另一个语言的版本。每条线开一个会话，能并行，也容易互相踩。可以用下面的分工和交接方式减少冲突。

## 规矩

1. **渲染一次只跑一个。** 谁要跑 Remotion，先发消息占「渲染槽」，跑完通知释放。
2. **文件有主人。** 比如配音清单 `video/src/script/tts-manifest.json` 归渲染线管，配音线要装新配音，先征得人同意，再通知渲染线。改共用组件（镜头、转场、字幕）之前也先说一声。
3. **每条线维护自己的交接文档。** 用 [`templates/HANDOFF.md`](../templates/HANDOFF.md) 的结构。
4. **对方不在线就写交接文件。** 会话中断时消息发不出去，写进 `COORDINATION.md`（[模板](../templates/COORDINATION.md)），对方恢复后先读它。
5. **长期决定写进记忆。** 比如事实核查方式、成稿的改写范围、配音方向和素材授权状态。新会话先读这些约定，再开始工作。
6. **大改动等所有修改都定了再一次渲。** 合集尤其如此，不要每改一处就渲一次。
7. **本机资源有限。** 本地 TTS 模型一次只加载一个，和渲染错开；跑之前看空闲内存，低于项目设定的余量就等。

## 交接文档

结构固定为：

- **进展**：做完了什么，成片在哪、多长、检查结果。
- **拍板与约束**：人点过头的决定，以及「不要再提」的建议。这一节最重要。
- **试过什么**：失败的尝试和原因，免得下一个会话再踩一遍。
- **当前状态**：类型检查、测试、交付检查的结果；有没有在跑的后台任务；可以清理的残留。
- **下一步**：按优先级排，写清楚哪些要人先决定。

旧版交接文档备份一份再改，别直接覆盖。

## 换会话：一段能直接复制的提示词

额度快用完、上下文太长、或者要把一条线交给别的 agent 时，让当前会话写一段交接提示词：

```text
请生成接续说明，列出先读的文件、当前目标、已验证结果、并行分工和下一步。
使用项目内相对路径，真实本地信息留在私有交接记录中。
```

下面是重新编写的交接示例，不是原会话摘录：

```text
请继续处理 <任务>，先读 HANDOFF.md 和 COORDINATION.md 的最新状态。

目标：<本轮要完成的内容>。
已完成：<已验证的结果，不需要重复处理>。
待处理：<下一步与仍需确认的要求>。

文件分工：<其他工作线负责的文件与任务>。
修改前确认当前版本，正式渲染需要协调任务与资源。
本地路径和私有链接留在内部记录，公开摘要使用相对路径和通用描述。
```

## 汇报格式

让每个会话的汇报都用同一个结构，人才能只回一句话：

- **已完成**：带验证结果；
- **进行中**：预计多久；
- **没做**：为什么；
- **要你拍板的**：编号列出，每条给建议；
- **要你看的**：完整路径和时间点，使用最新成片时间码。

审稿类的汇报按类别编号（A 事实错误、B 口径、C 读音、D 要实机确认），人回「A1 改、A2 不改、B 按你的建议」就行。

## 踩过的坑

- **推送飞书逐字稿会重建整篇文档，评论会丢。** 先 pull 再 push，只让一个会话负责推送。
- **两个浏览器窗口标题一样。** 按标题找窗口的工具会把键盘输入落到另一个窗口里。给 agent 单独开一个配置目录的浏览器窗口。
- **只读浏览器。** 让 agent 看线上页面时约定：不点生成、不领奖励、不碰人机验证，改过的设置测完恢复，汇报里单独写一段「浏览器里我做了什么」。
- **API key。** 在网页上新建 key，弹窗里是完整的 key，agent 读页面时会进会话记录。存 key 用 `read -s` 从终端输入，别用 `pbpaste`（剪贴板里可能还是刚复制的命令）。
- **会话重启后名字会变。** 发消息前先查一下对方现在叫什么；后台脚本在会话重启后还会跑，但不再归会话跟踪，要自己确认进程结束了。
- **串联脚本。** `pgrep -f "<文本>"` 会匹配到脚本自己；zsh 里 `for f in $F` 不按空格拆分。
- **命令重名。** 自定义的 `pnpm pack` 和 pnpm 自带命令重名，会打出一个巨大的 tgz。
- **工作区位置要容易找到。** 在私有交接记录中说明位置，公开材料不写本机路径。
