# TTS 选型

先用小样选声音，再决定是否全量生成。这份文档保留选型方法，不列原教程的体量、具体声线、成本测算或本机性能数据。价格、额度和模型版本用之前重新核对。

## 先把内容做稳

模板默认用 Edge TTS 跑通台词、字幕和时间轴。内容还在大改时，不必急着换声音：换一次配音，每句话的长度都可能变，画面和目录也要跟着更新。

内容稳定后，再比较候选引擎。除了听感，还要看修改一句的成本、缓存、时间戳、调用限制和使用授权。

## 要比较什么

| 维度 | 怎么检查 |
| --- | --- |
| 长段听感 | 连续听一段操作说明，语气是否平稳，停顿是否自然 |
| 字句完整 | 是否漏字、加字、重复，数字和缩写是否念对 |
| 术语读音 | 能否指定读法，或通过配音写法表稳定修正 |
| 跨句一致 | 分批生成或补录后，声音、语速和音量是否接得上 |
| 修改成本 | 只改一句时，需要重生成多大范围，缓存如何失效 |
| 时间信息 | 是否返回逐字或逐词时间戳，缺少时如何做强制对齐 |
| 资源与限制 | 本地内存、云端额度、并发和限流是否适合预计任务量 |
| 授权 | 引擎、声线、参考音和输出用途是否符合对应条款 |

## 做一页试听

挑几句覆盖不同问题的文本。下面是重新编写的示例类型，不是原视频台词：

- 普通讲解：比较整体语气和长时间听感。
- 带多音字的操作说明：检查上下文读音和停顿。
- 带术语与缩写的句子：检查字母是否完整、术语是否稳定。
- 带数字和符号的句子：检查数字展开与自然念法。

每个引擎先选一个候选声线，念同一批文本。先统一响度，再并排试听；每句话旁边写明要关注的地方。选出候选后，再听完整段落。

`tts-lab/audition/build_page.py` 用来生成这种页面，也能打包为内嵌音频的单个 HTML。先运行 `demo_clips.py` 可以看模板示例，再替换为自己准备的候选音频。

## 估算成本

不要沿用别人的成片规模和耗时数据。用自己的台词总量和小样结果估算：

- 计费按字符、音频时长还是请求次数，标点和空格是否计入。
- 一轮配音之外，预留改稿、读音重试和试听的额度。
- 限流后的排队、失败重试是否影响交付时间。
- 本地方案把加载模型的开销、峰值内存和渲染占用一起考虑。

拿一个场景测完整流程，比只看接口响应时间更有用。选定后支持断点续跑，记录失败请求，避免重跑时重复消耗额度。

## 预置与参考音

引擎支持两种方式时，可以用相同的文本和语气做 A/B 试听。先用短段筛选，再扩大到完整场景，检查术语、长句和补录的一致性。

参考音会影响后续生成的语速和情绪。换语气时，把参考音一起检查；只允许使用有对应授权的声音。

不要把某句读得准当成整个声线都稳定，也不要默认参考音方式一定比预置好。保留试听结果，按自己的文本决定。

## 语气和语速

默认语气尽量简短，例如平静、清晰地讲解操作。各场景只补必要的变化，避免每一段都有强烈情绪。

轻微的速度调整可以通过 ffmpeg 的 `atempo` 处理，但要试听确认音质，并重新对齐字幕和画面。换 TTS 后，封面和标题里的固定时长也要检查。

## 批量生成

模板目前提供的是 Edge 的逐句配音脚本。下面是更换引擎时可采用的流程设计，不是模板内已经实现的另一套生产脚本：

1. 导出台词，应用 `tts` 念法、统一口播转换和当前引擎的术语规则。
2. 根据引擎表现决定逐句还是整段请求；过长的段落在自然边界拆分。
3. 缓存生成结果，缓存键覆盖文本、念法、声线、语气和影响输出的配置。
4. 做必要的响度与速度处理，再用时间戳或强制对齐工具定位句子。
5. 用听写筛选漏字、加字，用读音检查和人耳试听复查术语。
6. 对不合格的段落有限次重试，保留已合格且文本未变的版本。
7. 输出与 `video/src/script/tts-manifest.json` 兼容的清单，试听确认后安装。

并发和重试间隔按服务当前限制调整，遇到限流降低请求速度，不把一次小样的结果当成批量保证。

装入新配音前，先协调负责渲染的会话。切换引擎后停用旧的生成流程，避免旧脚本覆盖新清单。

## 自己录音

自行录音也能使用同一套台词和时间轴。先试录一小段，算上准备、重录、剪辑和后续补录，再决定是否适合整个项目。

模板的 `pnpm prompter` 生成按场景分屏的提词稿，多音字标拼音，编号与逐字稿一致。补录时保持相近的环境、距离和状态，念错后从完整句子开头重录。

## 授权与标注

- 核对引擎与服务条款，以及声线、参考音和输出的使用范围。
- 没有授权的真人或角色声音，不作为克隆参考。
- `edge-tts` 是第三方工具；模板能生成声音，不代表所有用途都获得了授权。公开或商用前按自己的用途核对条款。
- 投稿时按平台当前要求声明合成内容，使用他人素材时保留必要的署名。
- 凭据放在本地受保护的位置或凭据管理工具中，不提交到 Git，也不放进公开文档和日志。
