# 改片

以下是通用示例。把句子编号、场景和要求换成自己的，不直接使用原视频台词。

## 整体审稿

```text
先审查台词与画面，不要改文件。
把问题分为事实、措辞、读音和待实机确认四类，每条给编号。
写明句子或场景 id、当前内容、具体问题、建议改法和依据。
最后列出需要我决定的项目，我回复编号后再修改。
```

## 查事实

```text
请核对 <待确认的说法>，同时检查官方文档和当前页面。
记录依据与差异，无法确定的先标记，不写入口播。
浏览器只读检查，不触发生成、付款或其他账号操作。
结束后恢复检查时改变的设置，并说明实际操作过什么。
```

## 选素材

```text
把候选素材做成能查看大图、选择和排序的页面。
每张写明作者、来源、用途与展示方式，选完导出结构化数据。
完整展示重要内容，检查是否裁掉细节，别把内部剪辑备注放进视频。
```

## 改措辞

```text
检查 <段落> 是否把个人偏好写成了事实，或用了没有依据的效果保证。
列出原句、修改建议和原因，先给我看方案。
确定后同步修改台词、配音输入，以及受影响的标题和简介。
```

## 改动效

```text
请检查 <场景 id> 的镜头、高亮、光标和转场。
指出哪些动作影响看清操作，再给出适合现有版式的小样。
共用组件的修改需要检查其他场景，确认后再批量重渲。
```

## 控制返工

```text
这一轮先集中修改并提供小样，不要每改一处就渲染整个合集。
列出受影响的场景与集数，确认后只重渲需要更新的部分。
保留未改的成片，并记录还需要我检查的地方。
```
